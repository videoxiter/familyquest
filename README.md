# FamilyQuest

Семейный трекер домашних дел с уровнями, монетами, значками и лентой событий.
Одна семья, приватно: бэкенд целиком в Supabase, фронтенд — статика на GitHub Pages.

- Сайт: `https://videoxiter.github.io/familyquest/` (после включения Pages и заполнения переменных сборки)
- Идея и разбор: [IDEA.md](IDEA.md), [DESIGN.md](DESIGN.md)

## Что уже работает

- **Вход по аватару и коду** — ребёнку не нужна почта; логин и код выдаёт родитель.
- **Экран «Сегодня»** — задачи на день, один тап «Выполнил».
- **Два режима закрытия** — само (`auto`) или с проверкой родителя (`review`).
- **Монеты и опыт раздельно** — опыт только растёт, поэтому уровень никогда не падает.
- **Комбо** — серия дней даёт множитель до ×2.0.
- **«Долг» и «квест»** — обязательные дела без награды отделены от оплачиваемых.
- **Значки, лента с реакциями, призы и обмен.**
- **Админка** — очередь одобрения, задачи дня, участники, коды входа.
- **pg_cron** — создание ежедневных задач в 00:05 по Москве, закрытие просрочек каждые 5 минут.

## Как устроено

```
браузер (React + Vite, статика)
        │  REST / RPC (anon-ключ + JWT пользователя)
        ▼
Supabase ─ PostgREST ─► PostgreSQL
                        ├─ RLS-политики (кто что видит)
                        ├─ RPC-функции (вся бизнес-логика)
                        ├─ журнал баллов append-only
                        └─ pg_cron (расписание)
```

Своего сервера нет. Это осознанно: нечему падать, нечего обновлять, бесплатно, а баллы
нельзя подкрутить из браузера — формулы живут в SQL, а не в JS.

## Структура


## Быстрый старт

### 1. Supabase (~5 минут)

1. [supabase.com](https://supabase.com) → **New project**. Регион — ближайший (Frankfurt).
   Пароль базы сохрани в менеджере паролей.
2. **Authentication → Sign In / Providers → Email**: выключить **Confirm email**.
   Без этого после регистрации не будет сессии.
3. **SQL Editor → New query**: вставить целиком `supabase/apply_all.sql` → **Run**.
   Файл идемпотентен, его можно применять повторно.
4. **Project Settings → API**: скопировать **Project URL** и **anon public** key.

### 2. Ключи локально

```bash
cp .env.example .env.local     # Windows: copy .env.example .env.local
```

Вписать URL и anon-ключ. Файл `.env.local` в `.gitignore` и в репозиторий не попадает.

> anon-ключ публичен по замыслу — он всё равно уезжает в JS-бандл. Доступ к данным
> закрывают RLS-политики. Ключ `service_role` в браузере не используется нигде.

### 3. Первый вход

В SQL Editor посмотреть код приглашения:

```sql
select code from public.invites where used_at is null;
```

На сайте: **«Присоединиться по коду»** → код, логин `papa`, пароль от 6 символов.
Папа становится администратором. Дальше: **Админ → Семья → «Код входа»** для мамы и Алёши.

Даты рождения в стартовых данных — заглушки (год по возрасту 38/35/10). Поставь точные
в **Админ → Семья → Дата рождения**: возраст считается из даты, а от него зависит
коэффициент опыта.

### 4. Локальная разработка

```bash
npm install
npm run dev       # http://localhost:5173
npm test          # типы + smoke-тест миграций на PGlite
```

`npm run test:sql` поднимает настоящий Postgres в WASM, применяет миграции, регистрирует
двух участников и прогоняет одобрение, начисление, обмен приза и проверки RLS.

## Деплой

GitHub → **Settings → Secrets and variables → Actions → Variables**:

| Переменная | Значение |
|---|---|
| `VITE_SUPABASE_URL` | Project URL |
| `VITE_SUPABASE_ANON_KEY` | anon public key |

Затем **Settings → Pages → Source: GitHub Actions**. Первый пуш в `main` запускает
`.github/workflows/deploy.yml`, сайт появляется на `https://<логин>.github.io/<репозиторий>/`.

Переменные — именно Variables, не Secrets: anon-ключ публичен, а Variables проще
редактировать. Если их не заполнить, сборка пройдёт, но приложение покажет экран настройки.

## Правила игры

```
монеты = round(вес × множитель события)        только если сделано в срок
опыт   = round(монеты × коэффициент возраста × множитель комбо)

коэффициент возраста:  <8 → 1.8 | 8–10 → 1.6 | 11–13 → 1.4 | 14–17 → 1.2 | 18+ → 1.0
множитель комбо:       1.0 + 0.1 × floor(min(серия, 30) / 3)   максимум ×2.0
```

- **Долг** (`kind = 'duty'` или вес 0) — задача без награды. Комната, своя посуда.
- **Квест** — оплачивается.
- **Опоздание** — статус `approved`, но 0 монет и 0 опыта. Без штрафа.
- **Штрафы выключены по умолчанию.** Включаются вручную:
  `update public.families set settings = settings || '{"fines_enabled": true}'::jsonb;`
  Тогда просрочка списывает 20% веса задачи, не уводя баланс ниже нуля.
- **Возрастной коэффициент влияет только на опыт** — монеты за одинаковую работу равны
  у всех. Иначе «ребёнку платят больше за меньшее» и это портит отношения.

## Ближайшие шаги

1. **PWA** — манифест, иконки, оффлайн-оболочка, установка на домашний экран.
2. **Telegram-уведомления** — `pg_net` + бот: напоминание за час, «одобрить» прямо в чате.
3. **Недельный дайджест** — воскресный отчёт по семье.
4. **Месячные звания** — по проценту выполнения личного плана (95 / 85 / 70).
5. **Баффы и семейный босс** — объявленные события, общая цель.

## Ограничения

- **Free tier Supabase**: 500 МБ базы, проект может уйти в паузу после долгого простоя —
  разбудить можно в дашборде. `pg_cron` работает, расписание в UTC (21:05 UTC = 00:05 МСК).
- **Репозиторий публичный**: виден код и стартовые данные, но не данные семьи — они в базе
  и закрыты RLS. Коды приглашений генерируются случайно и в репозитории их нет.
- **Бэкапы**: у free tier нет point-in-time recovery. Раз в месяц делай
  `pg_dump` из дашборда и храни файл отдельно.
- **Часовой пояс** семьи — `families.timezone`, по умолчанию `Europe/Moscow`.

## Безопасность

- `.env` и `.env.local` в `.gitignore`; ключи в коде отсутствуют.
- Запись в домен (задачи, баллы, призы) идёт только через `security definer` RPC —
  ребёнок не может поднять себе монеты прямым `UPDATE` (проверяется тестом).
- Журнал баллов append-only: исправление — только обратной транзакцией.
- Все чтения ограничены своей семьёй через RLS.
